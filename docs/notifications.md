# Telegram 通知

## 配置

通过 BotFather 创建 Bot，在设置页填写 Bot Token、Chat ID 和 Telegram API 地址，先向机器人发送 `/start`，再启用所需通知类型

默认 API 地址为 `https://api.telegram.org`。无法直连时，可配置部署进程的 HTTP(S) 代理或自有 API 反向代理；代理配置见部署文档

通知示例显示消息格式及对应推送频率，预览不会实际发送消息。“测试通知”会向已配置 Chat ID 发送一条测试消息，使用前应确认接收目标

## 类型与频率

消息标题仅使用三色圆点：🟢 动作成功、恢复、汇总及测试通知，🟠 告警及非异常状态变化，🔴 异常。异常优先于动作类型显示，关机完成使用绿色，关机失败使用红色

Telegram 消息、通知示例和最近通知共用图标规则；面板操作反馈使用绿色成功图标与红色错误图标

| 类型         | 默认 | 内容与触发频率                                               |
| ------------ | :--: | ------------------------------------------------------------ |
| 保活开机     |  开  | 每次保活启动核实成功后发送一条；正常运行不发送               |
| 流量告警     |  关  | 达到阈值时提醒一次，持续超限不重复；恢复后再次超限可重新提醒 |
| 流量关机     |  开  | 流量保护关机核实成功后发送结果                               |
| 流量保护恢复 |  关  | 流量保护由触发状态恢复时发送                                 |
| 定时开关机   |  关  | 定时动作核实成功后发送结果                                   |
| 手动开关机   |  关  | 手动动作核实成功后发送结果                                   |
| 开关机异常   |  开  | 动作失败或需要核对结果时发送；与成功结果通知单独选择         |
| 实例状态变化 |  关  | 检测到状态变化时发送                                         |
| 检测异常     |  开  | 相同查询异常提醒一次，恢复后可再次提醒                       |
| 检测恢复     |  关  | 异常检测恢复成功时发送                                       |
| 账单查询异常 |  开  | 相同账单或余额查询异常提醒一次                               |
| 账单查询恢复 |  关  | 查询从异常恢复成功时发送                                     |
| 每轮汇总     |  关  | 完整规则检测结束后发送，包含手动刷新触发的检测               |
| 每日汇总     |  开  | 按设置时间及指定时区每天发送一次，默认北京时间 00:00         |

总开关关闭、Token/Chat ID 未配置或通知类型未勾选时，该类自动通知不发送。全部取消选择会关闭所有自动通知；总开关开启且配置完整时，仍可手动发送测试通知

取消某类型后，尚未发送的对应队列消息会跳过。恢复类型可以独立关闭，不要求与异常类型同时选择

## 汇总口径

未接入实例时不生成每轮汇总或每日汇总；首次加载尚无实例数据时不发送空日报，也不占用当天的日报去重标识，数据恢复后在补发窗口内正常生成

每日汇总包含实例数量、运行及停止数量、实例状态、月度共享流量、实例费用和可用余额，消息内列出有限数量的实例和余额，避免超出 Telegram 消息长度

同一账号的共享流量与余额不会因多台实例而相加。账单未启用或不可用时，沿用实际状态展示，不生成虚构费用

日报按日期生成唯一事件，正常情况下每天一条；计划时间后的十分钟内支持补发，超过窗口不会补发整日历史。已经入队的日报在网络恢复后仍可继续投递

## 队列、重试与日志

消息先写入本地持久化队列，后台每五秒处理最多三条。动作通知在结果核实后入队，发送时间可能受队列积压、网络及 Telegram 限流影响

网络失败采用递增退避，最多尝试五次；Telegram 返回 `retry_after` 时暂停通道，至少等待指定时长后继续投递。相同事件使用去重标识，避免后台重复入队

日志记录通知入队、投递成功、重试次数、失败原因与下次重试时间。最终失败的消息保留失败记录，不保证每条通知均能送达

系统日志最多保留最近 5,000 条，各日志类型共用此上限，超过后自动删除最早的记录。日志页支持每页显示 20、50 或 100 条，默认 20 条，浏览器记住每页条数选择；筛选和每页条数变化时返回第一页
